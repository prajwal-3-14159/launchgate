LAUNCHGATE

Find what blocks your release in each market before counsel does.

A team shipping to Japan and the EU has to check security, privacy, licences and trade rules for each market. Today that is a late, manual review.

LaunchGate takes a repo URL and target markets and returns a market × domain matrix of release blockers.

Every finding ties a line of code to a dated web source.

How it works

Step 1

Daytona sandbox

Clones the repo and runs detect-secrets, pip-audit, pip-licenses and bandit.

Step 2

Fact sheet

An open model on Nosana reads the scan and key files and lists the facts.

Step 3

Tavily rules

Fetches current rules per market × domain; enriches vendors, CVEs and licences.

Step 4

Market agents

AgentField reasoners, one per market × domain, match facts to rules.

Step 5

Evidence check

Code drops any finding without a fetched source and a real line.

Step 6

CodeAF patch

Writes a patch for a code-fixable blocker; Daytona re-scans.

Step 7

HTML report

Writer agents produce an HTML report from the run.

The differentiator

The model proposes; code decides.
