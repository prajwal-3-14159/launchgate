How it works: the model proposes, code decides

Step 1

Daytona sandbox

Clones the repo and runs detect-secrets, pip-audit, pip-licenses and bandit.

Step 2

Fact sheet

An open model on Nosana reads the scan and key files and lists the facts.

Step 3

Tavily rules

Fetches current rules per market × domain; enriches vendors, CVEs and licences.

Step 4

Market agents

AgentField reasoners, one per market × domain, match facts to rules.

Step 5

Evidence check

Code drops any finding without a fetched source and a real line.

Step 6

CodeAF patch

Writes a patch; Daytona re-scans and runs the repo’s own tests. Rejected patches are retried with the reason.

Step 7

HTML report

Writer agents produce an HTML report from the run.

The differentiator

No fetched source and real line, no finding.

THE RULES IT FOLLOWS

  • Every finding cites a source fetched in that run, or it is dropped
  • Repo code runs only in a throwaway sandbox
  • A patch counts only when the scanner is clean and your own tests pass
  • Nothing is pushed for you: you get a diff and a report to review
  • It never says a product is cleared; it is triage before counsel
